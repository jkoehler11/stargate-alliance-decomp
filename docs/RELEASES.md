# Releases

PLAN 8.4 defines six milestones. Their notes are **generated**, not written: the numbers come out of the
committed artifacts, so two releases can be diffed and a stale figure is a failing check rather than a
stale sentence.

    python3 tools/release-notes.py --milestone a > /tmp/notes.md
    git tag -a v0.1.0 -m "milestone A: inventory and tooling"
    gh release create v0.1.0 -F /tmp/notes.md --title "v0.1.0 — inventory and tooling"

Version scheme: `v0.<milestone index>.0` for the milestone release, patch numbers for fixes after it.
A release is cut from `main` only after its milestone's exit criteria are met — never from a branch.

## The milestones and where they stand

| | milestone | exit criteria | status |
|---|---|---|---|
| A | inventory and tooling | every artifact in the repository can be regenerated from the dump | **met** |
| B | scripts decompiled | all classes decompile to readable source and the tree is complete | partial |
| C | scripts compile | the tree compiles with a UE2 build of the same generation | not started |
| D | bytecode match | recompiled bytecode matches the original function for function | not started |
| E | playable rebuild | a rebuilt package set boots and plays a mission in the emulator | not started |
| F | asset-complete rebuild | rebuilt packages plus original assets reproduce the build | not started |

**Why A is met:** every committed artifact has a target or tool that regenerates it — 13 `make` targets and
20 tools, mapped step by step in `docs/BUILDING.md` — and `make ci` (which never touches the game) verifies
the committed shapes: the symbol map regenerates, the docs' counts match, all 15,423 symbol addresses land
inside the image's sections, and the status table is current. `make inventory`, `make ghidra`, `make
symbols` and the content indexes rebuild the rest from the dump.

**Why B is only partial:** all 2,319 classes are reconstructed at L0 (readable source), but "the tree is
complete" also means the reconstruction is *right*, and the only evidence for that is the 2006 oracle, where
204 of 291 classes agree, 56 drift, 16 diverge and 15 are oracle-only (`docs/ORACLE_DIFF.md`). Calling that
complete would be claiming something the measurement does not support.

**C through F are not started.** The compile loop needs a matching `ucc` under Wine (3.6); bytecode match
needs the disassembler/comparator (3.7); E and F depend on both. The asset export (5.1) is blocked on an
external viewer and is what F additionally needs.

## What goes in a release body

The generator emits three things, in this order: the milestone's exit criteria, a table of measured state
with the artifact each number came from, and the checks a reader can run. It also states what the release
is *not* — no game data, and no rebuilt package until C lands. That last paragraph is not boilerplate: it
is the difference between a reader trusting the numbers and a reader discovering later that "13.29% named"
does not imply anything is playable.

## Notes for whoever cuts the next one

* Regenerate first: `make status` (the README table), then `make ci`. A tag whose status table is stale is
  the one failure mode this scheme does not catch on its own.
* Attach nothing. The release points at a commit; artifacts are regenerated by the reader from their own
  dump, which is the only form the licensing allows (`docs/LEGAL.md`).
* If a milestone's exit criteria changed while it was in progress, change them in the PLAN in the same PR
  that cuts the release, so the tag and the criteria never disagree.
