# The package check file, measured

`System/Packages.md5` is the game's own integrity list, and PLAN 1.4 asks which shipped packages
satisfy it. The answer is none, and the reason matters more than the answer: the file is not a list
of MD5s of the files as shipped. This is what it is instead, and what that costs PLAN 6.2.

    python3 tools/package-check.py DUMP/.../System -o inventory

## What the file is

It is an **Unreal Engine 2 package**, not text:

| field | value |
|---|---|
| tag | `0x9E2A83C1` (UE2 package) |
| version / licensee | 130 / 4 |
| package flags | `0x00000001` |
| name table | 175 entries at `0x44` |
| exports | 168 at `0x43D3` |
| imports | 2 at `0x43C5` (`Core`, `Engine`) |
| size | 20,111 bytes |

The 168 exports are `PackageCheckInfo0` … `PackageCheckInfo167`, and the name table declares a `md5`
property alongside them — 16 bytes per package, which is why the file is 20 KB rather than 2 KB.
There are **168 entries for 18 shipped `.u` files**: the list covers the whole game's package set, not
just the scripts in `System/`.

## What it does not match

For each of the 18 packages, four plausible hash schemes were computed and searched for in the file:

| scheme | result |
|---|---|
| `md5(file)` | absent for all 18 |
| `md5(file[4:])` (tag stripped) | absent for all 18 |
| `md5(file[16:])` | absent for all 18 |
| `md5(first 16 bytes zeroed)` | absent for all 18 |

`inventory/package_check.csv` records all 18 with their real digests and `recovered_from=absent`. So
the stored digests are **not** a hash of the bytes in `System/` under any of the obvious framings. The
likely explanations, none of them yet measured: the runtime hashed the package after its own loader had
normalised it (name/import reordering), the packages in this dump were rewritten by whoever extracted
them, or the digest covers a serialised subset rather than the file.

## Why this matters for PLAN 6.2

6.2 asks how to satisfy or bypass this check so a rebuilt package can ship. This narrows it: the check
data cannot be regenerated by hashing a `.u` and dropping the digest in — the transform has to be
reproduced first, which means reading the `md5` property out of the export stream and matching it to a
package name. Both sides of that are inside the same 20 KB file, so it is tractable: parse the compact
export table, take the 168 property values in order, and pair them with the name table's
`PackageCheckInfoN` order. Until that is done, **no claim is made about which digest belongs to which
package**, and the CSV says `absent` rather than inventing a mapping.

## Not measured

* The transform that produced the digests (the open question above).
* Which of the 150 packages not shipped in `System/` the remaining entries describe.
* Whether the runtime compares digests at all in this build, or only when a command-line/`-check` path
  is taken — that needs the probe in UNKNOWNS U5/7.3 territory.
