# Custom and non-obvious formats

The dump mixes four universes under one tree. The extension tells you the family; the first bytes
tell you the reader.

`inventory/formats.csv` is generated by `tools/formats.py` from the committed manifest (counts) plus
a sample directory (container detection):

| extension | files | container | tool | doc |
|---|---|---|---|---|
| `.sgs` | 9 | Unreal package (130/4) | UELib / `Sg1Tool save` | [sgs-checkpoint.md](sgs-checkpoint.md) |
| `.sgp` | 3 | INI | `configparser` | [sgp-profile.md](sgp-profile.md) |
| `.PRO` | 1 | INI | `configparser` | [sgp-profile.md](sgp-profile.md) |
| `.ka` | 3 | XML, `KARMA` 1.0 | `xml.etree` | [ragdoll-ka.md](ragdoll-ka.md) |
| `.kaw` | 1 | XML, `KAT_WORKSPACE` | `xml.etree` | [ragdoll-ka.md](ragdoll-ka.md) |
| `.lad` | 8 | opaque binary | not parsed yet | [lipsinc-lad.md](lipsinc-lad.md) |
| `.u` / `.unr` / `.utx` / `.ukx` / `.usx` / `.uax` | 18 / 73 / 170 / 83 / 91 / 55 | Unreal package | UELib, umodel | `docs/INVENTORY.md`, PLAN 5.1 |

Two surprises worth knowing before planning work:

- **A checkpoint is a package**, not a bespoke blob: `.sgs` carries a UE2 summary, name/import/export
  tables and tagged actor properties. That means it can be read with the same library as the game's
  own packages, and the "save format" work is a property-schema job, not a byte-level one.
- **The ragdoll files are XML**, so the `.ka`/`.kaw` loaders need no reverse engineering at all; the
  authoring convention (Karma 1.0) is documented in the file itself.

Rules: these notes describe layouts, field names and counts. No payload bytes, no property values,
no saved player data — see `AGENTS.md`.

## Regenerating

```
make formats SG1_DUMP=/path/to/dump      # inventory/formats.csv, inventory/sgs_schema.csv
```
