# The outer edge of a level's logic: the events sequences wait on (PLAN 5.2)

`inventory/event_wiring.csv` is one committed row per `.unr`, one per class that waits on an event, one per class
that fires one, one per fire property, and a corpus census row. It is generated by `tools/event-wiring.py`
(`make event-wiring`), which reads each map's property blocks and joins the names its actors wait on against the
names its actors fire.

A level in this build has no compiled script (`docs/MAP_SCRIPTS.md`: 0 of 73 maps export one). Its logic is placed
actors, and the previous read (`docs/MAP_ACTION_WIRING.md`) followed the **inner** edge of that graph — which
sequence's `Actions` array names which placed action. That page closed with the edge it could not follow:

> The outer edge is named events: `ACTION_WaitForEvent` carries an `ExternalEvent` name, so the next read is a join
> between the names the waiters wait on and the names the `TriggerEvent` actions fire.

This page is that join. An event here is a **name**, not an index, and the names sit in three places, all of them
property values of placed exports:

* a **wait site** — `ExternalEvent` on an `ACTION_WaitForEvent` (the scripted family) or a `MatActionWaitForEvent`
  (the scene family, counted apart for the same reason `Actions` had to be split: a cutscene wait is not a mission
  wait);
* a **fire site** — any other name-typed property whose spelling says event (`Event`, `StaticEvent`, `EventName`,
  `BumpEvent`, `OpenedEvent`, `SuccessEvent`, `DialogueFinishedEvent`, …). A property block carries only what an
  actor overrides, so an `Event` in a placed actor's block is a name a mapper set on purpose;
* a **`Tag`** — what a fired name resolves to, because `TriggerEvent('X')` addresses every actor tagged `X`.

Every statement on this page is a count of classes or sites. The event names themselves are game content and none
of them is written to the artifact or quoted here.

**A fire site's property is a declared `UNameProperty` on its class chain** in `inventory/class_properties.csv`, a different reader of a different artifact: **0** name-typed properties whose spelling says event and that census does not declare were refused rather than counted, because the property reader landing on an object name is a mis-parse and not a fire. The wait side needs no such guard -- `ExternalEvent` is the only property name it accepts.

Names compare case-insensitively in UnrealScript, so the join folds case; a name that differs only in case is a match, not a miss. Every count here is a class name or a number -- the names themselves are game content and none is written to the artifact.

**The wait side is a subset of the placements.** `inventory/map_export_classes.csv` counts 2722 placed `ACTION_WaitForEvent` actors over these maps, so the 2703 scripted wait sites leave 19 placements that state no `ExternalEvent`; no map has more wait sites than placements (73 of 73 maps agree, no exception). Those placements do not wait on nothing: the class looks its condition up with the default name, `None`, which the actor iterator does not filter on, so the first `TriggeredCondition` in the level decides whether the wait completes at once -- `docs/MAP_ACTION_PARAMETERS.md` names them by map, class and slot and counts the placements that state `bCheckRecentEvents` beside them.

**A wait site is not a wait for an event the level fires from its data alone.** 332 of the 2838 waits name something no placed actor fires, and 87 of those name a placed actor's `Tag` -- a name a `TriggerEvent` could address, but one nothing in the map addresses. Of the 245 that name nothing in their own map, 15 are fired by a *different* map -- a handful of names are conventions shared across levels rather than edges inside one -- and the rest are fired by nothing in any package, which is where native code and runtime-spawned actors take over from placed data.

## Reading a row

`kind=map` rows carry the per-map counts, `kind=waitclass` rows how many wait sites each class carries,
`kind=fireclass` rows how many fire sites each class carries, and `kind=fireprop` rows which property carries them
— a fire site's class says what fires the event, its property says under which of its own conditions. The corpus
row is `kind=census` and carries every total the prose quotes, so a re-render and a check read the same numbers.

Two arms are reported that are not matches, and they are the interesting half: `orphan_tag` counts wait sites whose
name is a placed actor's `Tag` (a name something *could* address, that nothing in that map addresses), and
`orphan_none` counts wait sites naming nothing in the map at all. `orphan_cross` is the subset of `orphan_none`
that some *other* map fires — names that are conventions across levels rather than edges inside one. The three arms
partition `orphan`, so `orphan_tag + orphan_name + orphan_none = orphan`.

## Controls

Three, each from a different reader:

* **the placement census** — `inventory/map_export_classes.csv` counts the placed `ACTION_WaitForEvent` actors, and
  no map may have more wait sites than placements. All 73 agree, and the difference is the number of actions that
  override no `ExternalEvent` at all.
* **the class census** — every fire property must be declared a `UNameProperty` on its class chain in
  `inventory/class_properties.csv`. The few name-typed properties whose spelling says event but that census does
  not declare are refused rather than counted: the property reader landing on an object name is a mis-parse, and a
  mis-parse must not become a fire site.
* **the tag arm itself** — `fires_landing` counts the fire sites whose name is a placed actor's `Tag`. A fire that
  lands on no tag still fires (the engine broadcasts the name), but a fire population that never landed would mean
  the two ends were not describing the same name space.

## What is not measured

* **The order of a wait's own following actions** — the `Actions` array is ordered (see `docs/MAP_ACTION_WIRING.md`),
  but which element runs after a wait is the array's order, not this join's.
* **Who fires the names that nothing in any package fires** — a name fired by native code, or by an actor spawned at
  runtime, has no placed actor to be found. That is the honest reading of `orphan_none` minus `orphan_cross`, and
  settling it needs a runtime trace (`tools/xemu/`), not another pass over the package.
* **Whether a fired name reaches an armed waiter at the moment it fires** — this is the map's static name space, not
  a schedule; a `bCheckRecentEvents` wait can be satisfied by an event that fired earlier, which this page does not
  model.
