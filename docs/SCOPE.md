# Scope

This document is the authority on what this project does and does not deliver. `PLAN.md` is the
task list; this is the boundary. If a task contradicts this file, this file wins and the task is
rewritten.

## Target

*Stargate SG-1: The Alliance*, Xbox prototype dated **2005-12-15**, dumped from an Xbox Debug Kit
and released by CVLT OF OSIRIS / Hidden Palace on 2019-05-06. Only that build. The PC-derived builds
and the later (2006) studio source tree are **not** targets — see "Out of scope".

## What "decompilation" means here

Four layers, each reconstructed independently and each verified against the original build rather
than judged by eye:

| Layer | Deliverable in this repo | Repo-visible? |
|---|---|---|
| Script | every class/state/function of the 18 shipped `.u` packages as readable `.uc` | no — game-derived, local only |
| Native | `default.xbe` loaded, symbolised and annotated; game modules reconstructed as C | symbol map + notes only |
| Assets | extraction tooling and a manifest schema for maps, textures, meshes, audio, speech | tooling only |
| Rebuild | pipeline that recompiles our `.uc` tree into packages that boot in xemu | pipeline only |

Decompiled scripts, extracted assets and rebuilt packages are **derived from a copyrighted work**.
They are produced into a local working tree and never committed (see `docs/LEGAL.md`). What is
committed is original tooling, generated *metadata that describes structure without reproducing
content* (counts, names of engine classes, addresses, sizes, hashes), and documentation.

## Verification tiers

Every reconstructed function/class carries one of these grades. The scoreboard lives in
`docs/MATCHING.md` and is regenerated by `make inventory`, never hand-edited.

| Tier | Meaning | Machine check |
|---|---|---|
| L0 | present — the object exists in our tree | object count matches original |
| L1 | compiles — our source builds against a matching `ucc` | compile error count = 0 |
| L2 | structural — recompiled bytecode matches the original opcode sequence | ≥98% of opcodes equal per function |
| L3 | byte-exact — identical serialized function body | exact match |

L3 is a bonus, not a requirement: Perception's own `ucc`/ucpp toolchain is gone, so exact bytes are
only realistically reachable on small packages. **L2 is the success criterion for the script track.**

## In scope

- Full inventory of the dump: packages, classes, `native()` indices, XBE module map, formats.
- UnrealScript reconstruction to the tier above, including `defaultproperties`, enums, structs,
  states, latent functions and replication blocks.
- Naming and documenting the native side: VM core, native dispatch table, and the game modules
  (`stargategame`, `stargatevehicles`) decompiled to readable C.
- Asset/level extraction and a cut-content report, because the prototype contains content that
  shipped in no later build.
- A rebuild path that boots in an emulator, plus the CI that proves it still does.

## Out of scope

- **Writing a new engine.** No renderer rewrite, no port, no netcode work, no remaster.
- **Bit-exact engine reconstruction.** Engine modules are named and documented where script reaches
  them; wholesale decompilation of `Engine`/`Core` is not attempted.
- **Redistribution of anything derived from the game.** Not negotiable, see `docs/LEGAL.md`.
- **The 2006 studio source as ground truth.** It is a private cross-check used for triage and to
  measure drift; our output is reconstructed from the 2005 binary, and differences are findings.
- **Multiplayer/networking behaviour** beyond what is needed to load a map.
- **Retail-hardware certification.** Boot verification is xemu-based first; real hardware is a
  stretch goal.

## Definition of done

1. `make verify-dump` passes on a clean checkout against an untouched dump.
2. `inventory/decompile_coverage.csv` reports 100% of classes decompiled, 0 compile errors.
3. `docs/MATCHING.md` reports ≥98% of functions at L2 or better.
4. Every `native()` declaration in the packages resolves to a named address in `symbols/xbox.map`,
   with zero unnamed functions left in the two game modules.
5. `tools/build.sh` produces packages that boot to the title screen and load a mission in xemu,
   with screenshot and log evidence committed under `docs/evidence/`.

Nothing less than all five counts as finished; each is individually falsifiable, which is the point.
