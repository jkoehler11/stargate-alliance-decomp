# Where a level's logic lives (PLAN 5.2)

`inventory/map_script.csv` is one committed row per `.unr` plus the carrier rows and a corpus census row. It is
generated by `tools/map-script.py` (`make map-script`), which walks the 73 maps as packages and counts, per map,
the export classes a compiled script would be made of, the `TextBuffer`s that would carry its source, the `Level`
export's child exports, and the actors that carry a level's logic instead.

## Why the question is asked of the export table

PLAN 5.2 leaves one item open in exactly these words: "the `Level` export's script sequence is separate from the
actors' properties and unread". Three pages depend on that read -- `docs/systems/OBJECTIVES.md` says mission
logic is level script, `docs/systems/AUDIO.md` defers "which cue is unused by the shipped maps" to the level
scripts, and `docs/MAP_EXPORTS.md` lists "anything the level script does" as unmeasured.

Reading a level script means having a reader for its text first. Asking whether one exists does not: in UE2 a
compiled script is **exports** -- `Function`, `State`, `ScriptStruct` -- and a class that ships source carries a
`TextBuffer`. A level script's members hang off the map's `Level` export as children. All four counts come out of
the export table this repository already parses, so the question costs one sweep and no new format.

The answer this build gives is a negative, and a negative on its own would read as "no mission logic". So the same
walk counts the carriers: the placed `ACTION_*` latent scripted actions (mission flow), the scripted-sequence
actors that reference them, and the triggers. Their per-map `ACTION_*` totals are then checked against
`inventory/map_export_classes.csv`, a class histogram measured by 5.2's other reader over the same exports --
agreement there is what says this walk is naming actors and not their templates.

## What this settles, and what it does not

**Settled.** No map carries compiled script, so 5.2's open item has no text behind it to read: a T3D dump cannot
recover a level script because there is none, and the `Level` export's payload is the level's tables (the model,
the actor list, the reach specs), not a script. The mission logic the objectives page attributes to level script
is therefore **placed actors** -- `ACTION_*` scripted actions driven by sequence actors -- and the per-map counts
here are that claim's evidence. [`docs/systems/AUDIO.md`](systems/AUDIO.md)'s cue question changes shape rather
than closing: an unused cue is not "one no level script names", it is one no placed actor's properties name.

**Measured since** (`docs/MAP_ACTION_WIRING.md`, `inventory/action_wiring.csv`, `tools/action-wiring.py`): the
`Actions` array that orders a sequence is a property value, and it decodes as 1-based export indices into the same
map package -- so *which sequence runs which action* is a join inside one package, and *whether a placement runs at
all* is answered per action. Of the **18,510** actions the maps place (by class hierarchy: `Action_PLAYANIM` is
placed 227 times and the `ACTION_` prefix cannot see it), **16,886** are named by some sequence's array and
**1,624** are named by none.

**Still not measured.** Two things, both outside that read: the order *within* an array, and whether the sequence
that names an action is itself activated -- so the wiring is the inner edge of a map's flow graph, not the whole
graph.
